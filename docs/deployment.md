# Deployment

## Docker Compose

```bash
cp .env.example .env        # set POSTGRES_PASSWORD, ANTHROPIC_API_KEY, CORS_ORIGIN
docker compose up -d --build
open http://localhost:8080
```

Services: `postgres` (volume `pgdata`), `redis` (AOF, volume `redisdata`), `backend` (Fastify, runs migrations on boot, BullMQ worker, cron jobs, Binance WebSocket), `frontend` (nginx serving the SPA and proxying `/api`, with SSE-safe settings). Only the frontend port is published (`FRONTEND_PORT`, default 8080); Postgres and Redis are internal.

## Production checklist

- Strong `POSTGRES_PASSWORD`; use `sslmode=require` in `DATABASE_URL` for managed databases.
- `CORS_ORIGIN` set to the public origin.
- Put TLS in front and set `APP_PASSWORD` (single-user password login). Every `/api/*` route except `/api/health` and `/api/auth/*` then needs a token from `POST /api/auth/login` (sent as `Authorization: Bearer`, or `?access_token=` for `/api/stream` and backtest CSV export). Tokens last `AUTH_TOKEN_TTL_HOURS` (default 168); changing the password revokes all of them. Because stream URLs carry the token, keep them out of proxy access logs.
- `.env` is git-ignored; never commit keys. The Claude key is only read by the backend container.
- Run a single backend replica (the WebSocket stream and cron jobs are per process). Scale horizontally only after splitting jobs/stream into a dedicated worker.
- Back up the `pgdata` volume (signals, AI history, backtests, portfolio).
- Logs are structured JSON (pino) on stdout; `LOG_LEVEL` controls verbosity.
- Health: `GET /api/health` (Docker healthcheck), `GET /api/status` for dependency state.

## Network notes

- `api.binance.com` / `stream.binance.com` can be blocked or flaky in some networks. The backend fails over to Binance's official public market-data endpoints (`data-api.binance.vision`, `data-stream.binance.vision`).
- Binance Futures (`fapi.binance.com`) is geo-restricted in several regions; derivatives then show "unavailable" and are excluded from AI context.

## Migrations

SQL migrations live in `database/migrations` (generated by drizzle-kit from `backend/src/db/schema.ts`) and are applied automatically at startup. To change the schema:

```bash
cd backend && npm run db:generate -- --name <change>
```

Indexes: `ohlcv(symbol, timeframe, open_time)` (primary key), `technical_indicators(symbol, timeframe, timestamp)`, `signals(symbol, timestamp)`, `signal_results(symbol, timestamp)`, `backtest_trades(backtest_id)`, `ai_analysis(symbol, timestamp)`.

## GitHub Pages (frontend) + separate backend

GitHub Pages only serves static files, so the **frontend** is deployed there and the **backend** (API, PostgreSQL, Redis, jobs, Claude key) runs elsewhere.

Workflows (`.github/workflows/`):

| Workflow | Trigger | What it does |
|---|---|---|
| `ci.yml` | push to `main`, pull requests | Backend typecheck/build/tests, frontend build/tests, Docker image builds |
| `pages.yml` | push to `main` touching `frontend/**`, manual | Builds the SPA with base `/crypto-insight/` and deploys to Pages |
| `backend-image.yml` | push to `main` touching `backend/**`, manual | Publishes `ghcr.io/<owner>/crypto-insight-backend:latest` |

Setup:

1. **Settings → Pages → Source: GitHub Actions.**
2. Deploy the backend somewhere reachable over HTTPS (any Docker host using `ghcr.io/<owner>/crypto-insight-backend`, plus PostgreSQL and Redis — or `docker compose` on a VPS / your own machine behind a tunnel).
3. On the backend set `CORS_ORIGIN=https://<owner>.github.io` (plus any other origins).
4. **Settings → Secrets and variables → Actions → Variables → `VITE_API_URL`** = backend origin, e.g. `https://api.example.com` (no trailing slash). The Claude key stays on the backend only.
5. Re-run the "Deploy frontend to GitHub Pages" workflow.

For a backend-only server use `deploy/docker-compose.server.yml` (backend + PostgreSQL + Redis, API bound to `127.0.0.1:3000` for a reverse proxy):

```bash
cp .env.example .env   # set POSTGRES_PASSWORD, ANTHROPIC_API_KEY, CORS_ORIGIN
docker compose -f deploy/docker-compose.server.yml --env-file .env up -d --build
```

Reverse proxy notes: the SSE endpoint `/api/stream` must not be buffered (`proxy_buffering off;` in nginx; Caddy streams by default) and needs a long read timeout.

Until `VITE_API_URL` points at a running backend, the Pages site shows "Backend API unreachable".
